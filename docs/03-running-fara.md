# Запуск Fara на Windows

Скрипт `scripts/start-fara.ps1` запускает локальный `llama-server` для модели Fara. Он рассчитан на проверенную конфигурацию Windows с RTX 3090 24 ГБ, но настройки являются стартовым профилем, а не доказанным оптимумом качества или скорости. Модель остаётся в Windows и не помещается в Docker.

Проверенная сборка сервера: `W:\LAMA\llama\llama-server.exe`, revision `9631 (6e14286ed)`. Модель по умолчанию: `W:\LAMA\Fara\Fara1.5-9B-Q4_K_M.gguf`; проектор по умолчанию: `W:\LAMA\Fara\mmproj-Fara1.5-9B-bf16.gguf`. Если проектор находится в другом месте, передайте `-MmprojPath`. Скрипт завершится с понятной ошибкой при отсутствующем файле или несовпадающем наборе флагов; он не включает текстовый режим и не переключается на CPU автоматически.

## Проверка конфигурации

Из корня проекта:

```powershell
.\scripts\start-fara.ps1 -CheckOnly
```

Режим проверки читает `--version` и `--help`, проверяет executable, модель и проектор, а затем показывает итоговую конфигурацию и команду. Он не создаёт секреты, не пишет логи и не запускает модель. По умолчанию команда выводится без API-аутентификации. Если передан `-ApiKeyFile`, проверяется существующий непустой файл и показывается только его путь.

## Запуск

Запуск в текущем окне PowerShell:

```powershell
.\scripts\start-fara.ps1
```

Скрытый фоновый запуск:

```powershell
.\scripts\start-fara.ps1 -Background
```

Фоновый режим ждёт до 120 секунд ответ от `/health`. При готовности он показывает URL и PID; stdout и stderr остаются в `runtime\llama.stdout.log` и `runtime\llama.stderr.log`. Если процесс завершится при старте, скрипт сообщит exit code и пути к логам. По таймауту незавершившийся процесс не останавливается: его PID и логи выводятся для проверки.

По умолчанию сервер слушает только `127.0.0.1:8081`, контекст равен 16384 токенам, параллельность — 1. Для меньшего расхода памяти можно проверить контекст 8192:

```powershell
.\scripts\start-fara.ps1 -ContextSize 8192 -CheckOnly
.\scripts\start-fara.ps1 -ContextSize 8192
```

Можно заменить пути к артефактам и порт:

```powershell
.\scripts\start-fara.ps1 -ModelPath 'W:\models\Fara.gguf' -MmprojPath 'W:\models\mmproj.gguf' -Port 8082
```

Скрипт отказывается стартовать, если порт уже занят, и никогда не завершает чужой процесс. Не запускайте второй экземпляр на занятом порту. Для диагностики памяти сначала уменьшите `-ContextSize`, проверьте свободную VRAM и журнал stderr. Не рассчитывайте, что заявленные 24 ГБ целиком доступны модели: Windows, рабочий стол, KV cache, batch и мультимодальная обработка тоже занимают память. K/V cache оставлен в `f16` ради сохранения качества; при OOM проверяйте меньший контекст и batch на конкретном стенде до изменения профиля.

## Доступ без пароля и подключение из Docker

По умолчанию `llama-server` запускается без API-ключа и пароля. Скрипт не создаёт, не ищет и не читает `secrets\fara-api-key.txt` или другой ключевой файл. Сервер всё равно привязан к `127.0.0.1`; авторизация операторской панели и MCP остаётся отдельной.

При необходимости можно явно включить API-ключ из уже существующего непустого файла:

```powershell
.\scripts\start-fara.ps1 -ApiKeyFile 'W:\secrets\llama-api-key.txt'
.\scripts\start-fara.ps1 -ApiKeyFile 'W:\secrets\llama-api-key.txt' -Background
```

В этом режиме передаётся флаг `--api-key-file` с путём к указанному файлу. При фоновой проверке `/health` скрипт использует этот же ключ в Authorization-заголовке. Значение не печатается. Файл не создаётся и не меняется.

Проверка `/health` на Windows использует локальный endpoint. Docker-контейнер не может обращаться к `127.0.0.1` Windows как к своему loopback. До подключения из Docker отдельно настройте и проверьте маршрут Windows host gateway и адрес прослушивания. По умолчанию скрипт не открывает порт на LAN и не меняет firewall; не переключайте bind на `0.0.0.0`, пока не ограничили доступ сетевыми правилами. Проверяйте `/health` из того же контейнера и network namespace, где работает клиент модели, прежде чем считать маршрут готовым.

## Что проверить на стенде

Запуск не доказывает, что выбранные контекст, batch, projector и Fara chat template дают нужное качество или устойчиво помещаются в VRAM. Сначала проверьте `/health`, затем короткий запрос через OpenAI-compatible API с тем же API-ключом, текстовый запрос и запрос с изображением. Сверьте фактическое потребление VRAM, скорость, ошибки KV cache и совместимость шаблона. Эта сборка старше текущей converter card runtime; совместимость нужно подтвердить тестовым запросом на установленной версии. До таких измерений сохраняйте `f16` K/V cache и не повышайте `-Parallel`.
