## Исторический итог исходного аудита (до opt-in hints)

**Readiness audit завершён: NO-GO.** Из восьми различных live UI сценариев шесть прошли независимую проверку (`text_box`, `invalid_email`, `notify_then_click`, `radio`, `double_click`, `dynamic`); два не прошли (`checkbox`, `web_table`). G6 candidate/rollback/redeploy PASS с ограничением по control DB migration marker. Unit baseline, security matrix и model smoke прошли в своих заявленных пределах. Эти результаты не дают production GO при двух live path failures и неполном capacity/in-flight evidence.

### Исправления в этой ветке

- **Продукт:** чувствительные пользовательские значения редактируются в API/MCP ответах; повторные секретные значения создаются заново вместо копирования из прошлой задачи.
- **Продукт:** ограничено чтение chunked HTTP response body; при неизвестном результате отмена остаётся `RECOVERING` и требует review, без ложного терминального `CANCELLED`.
- **Продукт:** обновлён generic prompt — доверие к источникам, допустимые action shapes, работа с деревьями и формами. Это не исправляет все ошибки модели: checkbox и web_table всё ещё не проходят live проверки.
- **Тестовая инфраструктура:** уточнены test URLs и явное отключение cookie sync; исправлены exit/report/cleanup пути, владение старыми fixtures, quoting для Windows Docker и extension worker startup.
- **Проверка:** шесть native runtime wrapper тестов отмечены как skipped в итоговом pytest и не исполнялись на host; `test_runtime_audit` проходил отдельно в disposable browser image. Не считать тестовую инфраструктуру product capability evidence.

## Ограничения

- Пять ранних readiness1 DemoQA сценариев блокированы на источнике cookies до действий; screenshots и неизменный profile digest из той сессии подтверждают контекст, но не UI capability.
- READINESS1 сохранил только security summary 16 PASS, потому что его export не удался. Control3 позже успешно экспортировал полный отчёт 16/16 и выполнил cleanup/restore; он подтверждает реализованную auth/CSRF матрицу и короткий read-only API load.
- Readiness2 и targeted4 оставили task failures как фактические. В readiness2 были `MODEL_OUTPUT_INVALID` для checkbox и `TASK_EXPIRED` для web_table; после prompt change targeted4 checkbox shape error исчез, но задача всё ещё истекла и Desktop остался unchecked. Web_table повторно истёк. Более ранние readiness1 `COOKIE_SOURCE_UNAVAILABLE` не удалены из истории. Targeted4 runner не выполнил свой post-run profile digest check; отдельный read-only disposable-volume fingerprint был сравнен с control3 baseline и совпал.
- Hardened model smoke — локальная synthetic Chromium fixture с локальной generic model; он не проверяет Camoufox или полный UI/MCP путь.
- Xvfb audit попытка без `--init` не является результатом browser test. Cgroup snapshot также снят до старта Python.
- Native edge audit подтвердил iframe только на синтетическом fixture; dialog/upload BLOCKED, multi-window не проверялся.
- Параллельность и uncertain-dispatch recovery не закрыты. TaskRunner cancel покрыт только bounded smoke с одним planned action; он не доказывает in-flight cancellation.
- Первый deploy/rollback wrapper вызов не смог прочитать список browser containers; это устранено правкой quoting и повторным успешным isolated candidate → baseline → candidate циклом. Успех не доказывает control database migration совместимость: marker не проверялся.
- Task control smoke закончил в `recovering`, держал стабильные 2 секунды без новых planned actions и восстановил worker idle; это не доказывает остановку уже dispatched action.
- Live2 resource peak был ниже лимита и без OOM, но выборка короткая; она не доказывает длительную работу под нагрузкой.
