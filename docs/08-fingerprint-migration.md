# Миграция fingerprint действующего профиля

`worker.migrate_fingerprint` подготавливает конфигурацию fingerprint для существующего профиля, не читая и не меняя cookie. Сохранение выполняется только при явном запуске без `--dry-run`. Файл создаётся атомарно с правами 0600, без перезаписи существующего состояния. Сам профиль не изменяется. До отдельного ревью и создания состояния переключать действующий worker на новый режим нельзя.

## Источник и границы доказательства

Режим `--trusted-live-source` использует `CAMOU_CONFIG_*` живого процесса как источник конфигурации. Он проверяет путь профиля в аргументах процесса, цепочку предков до `python -m worker.app`, контейнер `9966c143d27b`, исполняемый файл браузера, отсутствие `user.js`, Camoufox 0.4.11 и закреплённые SHA-256 исходников старого worker, `async_api.py`, `utils.py`, `webgl/sample.py`, бинарного комплекта браузера и WebGL SQLite. Это проверка происхождения, а не независимое наблюдение значений через JavaScript. Отдельный режим без `--trusted-live-source` требует SHA-256 независимо наблюдённого user agent и размеры screen.

Старый worker вызывает `AsyncCamoufox` без пользовательских config и Firefox prefs. В проверенном `launch_options` значение `webgl.enable-webgl2` берётся из строки WebGL SQLite; `webgl.force-enabled` задаётся `true`. Помощник восстанавливает WebGL2 только если все строки, допустимые для ОС данного fingerprint, дают одинаковое значение. Если строки расходятся, версии или хеши отличаются либо присутствует `user.js`, он останавливается. Для текущего процесса все шесть строк допустимой ОС дают `true`. SHA-256 WebGL SQLite: `d293cabe7b546bf4ac3a2fb6c3cb6aee9891910659299d61fa2c88944d38c45d`.

В контейнере доступен только префикс container ID, а не Docker image ID. Поэтому **перед каждым запуском** с хоста необходимо отдельно проверить `docker inspect` и убедиться, что container ID равен `9966c143d27bef89ff5889a52e5eb0612c8a9205331f1072970243e38b30be32`, а image ID — `sha256:e48794864dd6d6fb01283b3f81bec9434ff207590208ce0f49fd4f93b75f16ac`. Проверка хешей файла worker на диске сама по себе не доказывает содержимое ранее загруженного Python-кода; её следует сопоставить с известным образом и запуском процесса. Любое расхождение блокирует миграцию.

## Проверка без записи

При заданных выше условиях выполняется `python -m worker.migrate_fingerprint --profile /app/runtime/worker-state/profiles/default --pid 56 --trusted-live-source --dry-run`. PID необходимо заново проверить до запуска. `--dry-run` не создаёт ни файл состояния, ни lock-файл; вывод ограничен хешем, количеством ключей, двумя булевыми настройками WebGL, режимом и признаком dry-run.

Запись через trusted-режим требует `--expected-sha256` с согласованным хешем dry-run. Helper откажет, если текущий fingerprint отличается. Образ и процесс необходимо проверить повторно непосредственно перед записью; проверка image ID остаётся внешней.

Проверка 2026-10-27 выполнена в памяти через stdin, без копирования helper и без записи в действующий контейнер: 39 ключей, две настройки, `webgl2=true`, `webgl_force_enabled=true`, SHA-256 `958ee3c18bd1870a48fdf4d4bb3f88d93217c54f4844a59cc671ca2521f9b3d3`. Это снимок живого процесса в момент проверки, а не разрешение на запись или перезапуск. Перед записью нужно повторить проверку и сравнить результат, поскольку процесс или состояние могли измениться.

После ревью проверка и `docker inspect` повторены, тот же снимок записан атомарно без перезапуска браузера. Повторное чтение подтвердило схему, SHA-256 и права `0600`; worker сообщил `ready=true`, один контекст и одну страницу. Состояние находится в томе `/app/runtime/worker-state`, а каталог профиля — в отдельном томе `/app/runtime/worker-state/profiles/default`. Для последующего запуска необходимо сохранить оба тома.

В отдельном контейнере без сети тест запустил старый Camoufox с Linux fingerprint, экспортировал конфигурацию живого тестового процесса, записал состояние и перезапустил профиль. До и после совпали наблюдаемые UA, platform, languages, screen, canvas и результат WebGL2, а viewport оставался 1440×900. Сравнение WebGL2 допускает отсутствие контекста и не гарантирует его доступность. Lock использует неблокирующую блокировку ОС и сохраняет inode: проверены конкуренция и освобождение после принудительного завершения владельца.
